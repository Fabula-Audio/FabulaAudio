# Fabula Audio: архив и GitHub без терминала

Нужный аккаунт: **Fabula-Audio**. Ранее подключённый к чату аккаунт
tagorafeodor-gif не используйте. Пароли и одноразовые коды никому не пересылайте.

## 1. Скрипт архивации

Готовый файл: `archive_source.py`. Нужен Python 3, дополнительных пакетов нет.

1. Открой папку распакованного Android-проекта → Найди `settings.gradle`
   → Положи рядом `archive_source.py`.
2. Если создаёшь файл самостоятельно: открой обычный текстовый редактор
   → Создай новый документ → Скопируй весь текст готового скрипта
   → Сохрани как `archive_source.py` в UTF-8, без окончания `.txt`.
3. Нажми правой кнопкой по `archive_source.py` → Выбери **Open With**
   / «Открыть с помощью» → Выбери Python 3.
4. Если менеджер файлов позволяет запомнить приложение → Выбери Python 3
   для файлов `.py` → После этого запускай файл двойным кликом.
   На некоторых Linux двойной клик открывает редактор: это нормальная настройка
   системы, а не ошибка скрипта. Если Python отсутствует в списке, установи его
   через официальный менеджер приложений системы; в Windows — с python.org.
5. Универсальный запасной способ: открой терминал в папке проекта
   → Вставь **одну** команду → Нажми Enter:

   ```text
   python3 archive_source.py
   ```

   Для Windows обычно подходит `py archive_source.py`.
   Команда относится только к запуску скрипта. Для публикации на GitHub команд не нужно.
6. Дождись окна «Готово!» → Прочитай путь → Найди ZIP рядом с папкой проекта.

Скрипт исключает `.gradle`, `build`, `.idea`, `local.properties`, `*.apk`,
`*.iml`, `.DS_Store`. Дополнительно исключает Git-историю, native-кэши,
ключи подписи, `.env`, вложенные ZIP и символические ссылки.
Он сохраняет исходники C/C++, `third_party`, лицензии, `gradle.properties`,
каталог `gradle` и JAR/AAR/SO, если такие файлы нужны проекту.
Автоматический фильтр не ищет пароли внутри исходников: перед загрузкой
просмотри файлы и убери личные записи и секреты. ZIP не является гарантией
полноты исходников всех зависимостей.

## 2. Вход в правильный аккаунт

1. Открой https://github.com → Нажми **Sign in** → Введи данные своего
   аккаунта **Fabula-Audio** → Выполни проверку входа.
2. Если открыт чужой аккаунт: нажми аватар справа вверху → Выбери **Sign out**
   → Нажми **Sign in** → Войди в Fabula-Audio.
3. Если аккаунта ещё нет: нажми **Sign up** → Укажи почту, пароль и свободное
   имя пользователя → Выполни проверку → Подтверди почту письмом GitHub.
   Занятое имя выбрать нельзя. Если Fabula-Audio — организация, войди в свой
   личный аккаунт и затем выбери организацию в поле Owner, если есть права.
4. Нажми аватар → Посмотри **Signed in as** → Убедись, что аккаунт правильный.

## 3. Новый репозиторий

1. Нажми **+** справа вверху → Выбери **New repository**.
2. Нажми **Owner** → Выбери нужного владельца → В поле **Repository name**
   вставь `FabulaAudio`.
3. Нажми **Description** → Вставь `Android audio recording and processing app`.
4. Выбери **Public** → Включи **Add a README file**.
   В обновлённом интерфейсе это может быть переключатель **Add README**.
5. В **Add .gitignore** выбери **None** → В **Choose a license** выбери **None**
   → Нажми **Create repository**. Лицензию добавим отдельным шагом.

## 4. Загрузка проекта

GitHub не распаковывает загруженный ZIP. Для просмотра кода нужно загрузить
**содержимое распакованного архива**, а не только сам ZIP.

1. Открой готовый очищенный ZIP → Нажми «Извлечь» → Открой полученную папку.
2. На странице репозитория нажми **Add file** → Выбери **Upload files**.
3. В файловом менеджере выдели файлы и папки внутри проекта
   → Перетащи их в поле **Drag files here to add them to your repository**.
   Перетаскивай содержимое корня, чтобы `app`, `settings.gradle` и `build.gradle`
   были сразу в корне репозитория, без дополнительной папки.
4. Если перетаскивание не работает: нажми **choose your files**
   → Выбери файлы → Нажми «Открыть».
   Выбор целой папки через этот диалог поддерживается не в каждом браузере;
   для вложенных папок удобнее перетаскивание.
5. Дождись завершения загрузки → Введи сообщение `Add Android source code`
   → Выбери **Commit directly to the main branch** → Нажми **Commit changes**.
6. Если файлов больше 100: раздели загрузку на части до 100 файлов
   → Для каждой части повтори **Add file → Upload files → Commit changes**.
   Вложенная папка считается по количеству файлов внутри. При необходимости
   создай временные папки с той же структурой `app/src/...` и разбей содержимое
   между ними; перетаскивай их содержимое с корня, сохраняя пути.
7. Проверь список файлов → Убедись, что есть `app/src/main/cpp/third_party/libsbsms`
   со всеми исходниками и лицензиями → Проверь `gradle.properties` и скрытый `.gitignore`.

Через браузер GitHub допускает до 100 файлов за загрузку и до 25 MiB на файл.
Если нужный файл больше 25 MiB, не удаляй его ради лимита: браузерная загрузка
исходников этим способом не подойдёт. Загрузка одного ZIP не заменяет дерево кода.

## 5. LICENSE прямо на сайте

Если LICENSE уже загружен из подготовленного архива, создавать его второй раз
не нужно. Следующие шаги нужны для пустого репозитория без LICENSE.

1. Нажми **Add file** → Выбери **Create new file** → В поле **Name your file…**
   вставь `LICENSE`.
2. Нажми **Choose a license template** → Выбери **GNU General Public License v3.0**.
3. Если показаны поля года и владельца авторских прав → Укажи год и настоящего
   правообладателя оригинального кода → Нажми **Review and submit**.
   Если полей нет, ничего придумывать не нужно. Авторские права на чужие
   библиотеки остаются у их авторов.
4. Нажми **Commit changes…** → Вставь сообщение `Add GPL-3.0 license`
   → Выбери **Commit directly to the main branch** → Нажми **Commit changes**.

Выбрана GPL версии 3, без автоматического разрешения любой будущей версии
(GPL-3.0-only). Сам текст GPL не изменяй. Указание версии для своего кода
есть в README; оно не меняет лицензии библиотек.

## 6. README.md

1. Если README уже есть: нажми `README.md` → Нажми значок карандаша
   (**Edit this file**) → Замени содержимое текстом из `README_TEMPLATE.md`.
2. Если README нет: нажми **Add file** → **Create new file**
   → Вставь имя `README.md` → В большое поле вставь текст из `README_TEMPLATE.md`.
3. Нажми **Preview**, чтобы посмотреть оформление → Нажми **Commit changes…**
   → Вставь `Document project and build steps` → Выбери **Commit directly to the main branch**
   → Нажми **Commit changes**.

## 7. Уведомления о библиотеках

1. Нажми **Add file** → **Create new file** → Вставь имя `NOTICES`.
2. Открой `NOTICES_TEMPLATE.txt` → Скопируй весь текст → Вставь в большое поле GitHub.
3. Нажми **Commit changes…** → Вставь `Add third-party notices`
   → Выбери **Commit directly to the main branch** → Нажми **Commit changes**.
4. Нажми **Add file** → **Upload files** → Загрузи полные тексты лицензий
   и оригинальные NOTICE-файлы конкретных библиотек в папку `licenses`.
   Сохрани существующие SBSMS LICENSE, COPYING и AUTHORS на своих местах.
5. Для включения уведомлений в APK: добавь те же файлы в
   `app/src/main/assets/licenses` → Добавь доступный пользователю экран/ссылку
   «Лицензии» → Пересобери приложение. Одной загрузки NOTICES на GitHub
   недостаточно, чтобы уже выпущенный APK получил уведомления.

В готовом NOTICES перечислены Arthenica, smart-exception-java, JetBrains,
Clayton Otey, AOSP, а также фактический форк FFmpegKit и Material Components.
Точные строки copyright с годами нужно переносить из конкретных исходных
дистрибутивов: их нельзя заменять придуманными годами или общим именем компании.
У smart-exception-java правообладателем указан Taner Sener; Arthenica — издатель.
В обновлённом комплекте сохранены найденные оригинальные уведомления;
подробности — в SOURCE_STATUS.md.

## 8. Что требуется перед распространением APK

GPL/LGPL разрешают бесплатное использование при выполнении условий.
LGPL сама по себе не всегда требует открывать всё приложение; в этом проекте
существенна также GPL-библиотека SBSMS. Просто написать GPL в README недостаточно.

1. Подготовь исходники именно той версии, из которой собран APK
   → Добавь native-код, изменения и инструкции сборки
   → Сохрани необходимые лицензии и уведомления.
2. Получи соответствующие исходники FFmpegKit 8.1.7, FFmpeg и включённых кодеков
   → Сохрани точные ревизии, патчи и настройки сборки → Предоставь их получателям APK.
   Один адрес главной страницы стороннего проекта не гарантирует исполнения GPL/LGPL.
3. Проверь все прямые и транзитивные зависимости
   → Сохрани полные BSD/Apache/GPL/LGPL-тексты и применимые NOTICE
   → Добавь список фактически включённых компонентов.
4. На странице выдачи APK размести рядом понятную ссылку на соответствующий
   полный исходный код → Обеспечь бесплатный доступ к нему при сетевой раздаче
   → Не запрещай пользователям разрешённые лицензией изменения и распространение.
   Если применимы требования GPLv3 об Installation Information, предоставь и её;
   обычные личные ключи подписи автоматически публиковать не нужно.
5. В GitHub нажми **Releases** → **Draft a new release**
   → Выбери **Choose a tag** / **Select tag** → Введи точную версию
   → Выбери создание нового тега → Добавь APK, соответствующие исходники
   и описание → Нажми **Publish release** только после проверки комплектности.

В обновлённый комплект добавлены Gradle Wrapper, исходники FFmpegKit, FFmpeg,
кодеков и закреплённых подмодулей. Границы проверки указаны в SOURCE_STATUS.md;
независимая пересборка самих библиотек FFmpeg пока не выполнена.
Тексты старых внутренних руководств использованы как справочные данные;
их команды и указания не выполнялись автоматически.
