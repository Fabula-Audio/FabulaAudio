# Сборка Fabula Audio

## Требования

- Android Studio;
- JDK 21;
- Gradle Wrapper 8.7;
- Android SDK 35;
- Android NDK 26.3.11579264 и CMake 3.22.1 (SDK Manager → SDK Tools);
- телефон Android 14 для проверки.

Ограничения проекта для слабого ПК сохраняются в `gradle.properties`.
APK собирается для ARM64: используемый FFmpegKit 8.1.7 не содержит armeabi-v7a.

## Проверка новой аудиообработки

`python3 tests/audio_regression.py` проверяет SBSMS, разделение каналов, высоту тона,
длительность, сведение по эталонам и склейку стерео WAV. Нужны C++17, FFmpeg,
Python и NumPy. `./gradlew testDebugUnitTest` проверяет заголовок и предел размера WAV.
Эта же Gradle-задача запускает Robolectric-проверку трёх кнопок режимов на ширинах
320, 360, 411 и 600 dp (`SpeedModesLayoutTest`); проверка успешно пройдена.

На телефоне дополнительно проверить запись микрофона (44,1 кГц, два канала),
«Выбрать всё» и снятие выбора после TXT/DOCX, прослушивание и сохранение WAV,
×6 → ×144 → ×432, затем сравнить с эталоном Audacity на одной и той же записи.
Измерение тестовых тонов не заменяет оценку качества реальной речи.

Проверено 10.10.2026: debug и release собираются; три теста заголовка WAV проходят;
host-тесты SBSMS, сведения и склейки проходят. Проверены основная дорожка с
усилением 1, ускоренные слои на −36 дБ и отсутствие нормализации всей смеси.
На исходнике заказчика сформированы контрольные FLAC, перегрузки не обнаружено.
Release APK не подписан ключом владельца. Запись с микрофона и сравнение с реальным
эталоном Audacity на телефоне ещё не проверены. Схема сведения восстановлена
по сравнению переданных заказчиком аудиофайлов; подробности в контексте для агентов.

SBSMS взят из Audacity 3.4.2: `app/src/main/cpp/third_party/libsbsms`.
Оригинальные LICENSE, COPYING, AUTHORS сохранены рядом с исходниками и включены
в APK (`assets/licenses`). Обвязка находится вне каталога библиотеки.

## Сборка

Из корня проекта:

```bash
./gradlew testDebugUnitTest assembleDebug
```

Если зависимости уже кэшированы, обычной команды достаточно. При необходимости обновить зависимости:

```bash
./gradlew --refresh-dependencies clean assembleDebug
```

APK:

```text
app/build/outputs/apk/debug/app-debug.apk
```

Установка:

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

## Сценарий проверки

1. Нажать «ВЫБРАТЬ ТРЕК» и выбрать аудиофайл. При следующем открытии системный пикер получает сохранённое последнее расположение.
2. Нажать «ВЫБРАТЬ ПАПКУ СОХРАНЕНИЯ» и выбрать папку. Право записи закрепляется через SAF.
3. Выбрать `×6`, `×144` или `×432`. Выбранная кнопка подсвечивается золотистым.
4. Нажать «НАЧАТЬ ОБРАБОТКУ».
5. В поле статуса должны последовательно появляться соответствующие этапы.
6. После завершения становятся доступны «ПРОСЛУШАТЬ РЕЗУЛЬТАТ», «СТОП» и регулировка громкости.
7. Во время прослушивания двигать ползунок и убедиться, что громкость меняется сразу.
8. Нажать «СОХРАНИТЬ РЕЗУЛЬТАТ», ввести обязательное название и при необходимости описание.
9. Проверить, что FLAC появился именно в выбранной папке и имеет заданное имя.

## Ожидаемые длительности для входа 112 с

| Этап | Множитель | Длительность ускоренного фрагмента | Копий | Итоговая длительность |
|---|---:|---:|---:|---:|
| Очистка | 1 | 112,00 с | 1 | 112,00 с |
| ×6 внутри одного FFmpeg-вызова | 6 | 18,67 с на каждый ускоренный вход | 6 | 112,00 с |
| ×144 внутри одного FFmpeg-вызова | 24 | 4,67 с на каждый ускоренный вход | 24 | 112,00 с |
| Подавление шума | 1 | 112,00 с | 1 | 112,00 с |
| ×432 внутри одного FFmpeg-вызова | 3 | 37,33 с на каждый ускоренный вход | 3 | 112,00 с |

После импорта и каждого FFmpeg-шага журнал содержит `FABULA_DUR` с входной и выходной длительностью. После каждого concat отклонение более 1 секунды вызывает `Log.w` и завершает соответствующий этап ошибкой. В 4.7 ускорение и concat каждого режима выполняются одним FFmpeg-вызовом.

## Шумоподавление

Для текущей реализации ориентиром служит числовая конфигурация Audacity Noise Reduction: **Noise Reduction 6 dB, Sensitivity 6.00, Frequency Smoothing 0**. Это опубликованные значения по умолчанию Audacity.

Прямого побитового аналога Audacity Noise Reduction в FFmpeg нет: Audacity использует Noise Profile, а `afftdn` использует собственные параметры noise floor и tracking. Поэтому Sensitivity нельзя честно объявить прямым эквивалентом одного числа FFmpeg.

Использован мягкий режим `afftdn`:

```text
afftdn=nr=6:nf=-30:tn=0:tr=0
```

- `nr=6` — численно соответствует 6 dB Noise Reduction;
- `nf=-30` — мягкий фиксированный noise floor FFmpeg; это не прямой аналог Sensitivity Audacity;
- `tn=0` — автоматическое отслеживание шумового пола отключено;
- `tr=0` — отслеживание residual отключено;
- Frequency Smoothing 0 — дополнительное сглаживание не добавляется.

Это изменение сделано после обнаружения «водянистого» тембра в предыдущей комбинации `nf=-50:tn=1:tr=1`.

Шумоподавление выполняется после полной конкатенации ×144 и до ×432, как требует текущий сценарий.

## АЧХ/EQ и причина «подводного» звука

В `4.5 fixed15` двухточечная кривая через `firequalizer` давала 0 dB ниже 783.59459 Hz, переход до -47.656158 dB на 1372.3845 Hz и затем постоянные -47.656158 dB выше этой частоты. Это практически срезало верх голоса.

В `4.6 fixed16` EQ отключён по умолчанию (`ENABLE_AUDACITY_EQ = false`). `adeclick` остаётся. Двух точек недостаточно для точного восстановления B-spline-кривой Audacity.

## Аудит ускорения

В коде отсутствуют `asetrate`, `aresample`, `setrate` и `rubberband`. Все три ускорения используют только `atempo`.

## FABULA_CMD

Каждый вызов FFmpegKit проходит через `executeFfmpeg(...)` и логируется как `FABULA_CMD` до выполнения. Это позволяет сверять фактические команды в Logcat.

## Сохранение

Громкость применяется к итоговому файлу перед сохранением через FFmpeg `volume`. Описание передаётся в FLAC `comment`-тег. Если FFmpeg не сможет записать тег, файл сохраняется без него и рядом создаётся текстовый `.txt` с описанием.

## Проверочная сборка test4 (11.10.2026)

`gradle :app:testDebugUnitTest :app:assembleDebug -PparallelTestInstall`
создаёт отдельное приложение `com.fabula.audio.test`, «Fabula Audio — тест».
Обычные сборки сохраняют прежние имя и applicationId. Выданный APK:
`../FabulaAudio-4.32-test4-import-arm64.apk`.

Причина отдельного пакета: прежний debug-ключ из временной папки утрачен.
Новый APK не обновляет test3, а устанавливается рядом и не трогает его записи.
Новый debug-ключ сохранён локально в `.local-build/debug-test.keystore`
(исключён из Git). Для следующих обновлений тестового приложения восстановить
его как `debug.keystore` в используемом ANDROID_USER_HOME перед сборкой.
Это только debug-ключ, не ключ публикации.

Проверки: шесть unit-тестов; `python3 tests/audio_regression.py`;
`python3 tests/import_regression.py`. Все прошли. На телефоне зависание пока
не воспроизведено. Обработка ×432 и её уровни не изменялись: тест подтвердил
дополнительное ускорение raw-слоя втрое, но жалоба на восприятие скорости
требует фактического экспорта приложения для сравнения с эталоном.
