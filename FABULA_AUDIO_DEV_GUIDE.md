# FABULA AUDIO — DEV GUIDE

## Назначение

Это инструкция для выпуска новых версий приложения **Fabula Audio** без необходимости заново разбираться в Android Studio.

Проект:
- package: `com.fabula.audio`
- Gradle wrapper: 8.7
- JDK: 21
- compileSdk/targetSdk: 35
- minSdk: 26
- Kotlin
- аудиообработка: FFmpegKit
- проект рассчитан в том числе на слабый компьютер, поэтому параметры Gradle менять без необходимости нельзя.

> **Главное правило:** перед изменением кода сделайте копию всего проекта. Не экспериментируйте с рабочей версией без резервной копии.

---

# 1. Что нельзя менять без отдельной причины

Не изменяйте:

- `UpdateManager.kt` — система автообновления;
- `res/drawable/exit_splash.png`;
- файлы иконки приложения;
- `res/xml/file_paths.xml`;
- аудиологику квантования ×6 / ×144 / ×432;
- зависимости без необходимости;
- `gradle.properties`.

Текущие ограничения Gradle:

```properties
org.gradle.jvmargs=-Xmx1024m -XX:MaxMetaspaceSize=256m -Dfile.encoding=UTF-8
org.gradle.parallel=false
org.gradle.workers.max=1
org.gradle.caching=false
android.useAndroidX=true
kotlin.code.style=official
```

Не увеличивайте `-Xmx` выше `1024m` на компьютере с 4 ГБ RAM.

# 4. Как менять versionCode и versionName

Откройте:

```text
app/build.gradle
```

Найдите:

```groovy
defaultConfig {
    applicationId 'com.fabula.audio'
    minSdk 26
    targetSdk 35
    versionCode 21
    versionName '4.21'
}
```

При выпуске следующей версии увеличивайте оба значения:

```groovy
versionCode 22
versionName '4.22'
```

### Правило

`versionCode` — целое число, которое должно расти при каждом новом APK.

`versionName` — версия, которую видит пользователь.

Например:

| Релиз | versionCode | versionName |
|---|---:|---|
| текущий | 21 | 4.21 |
| следующий | 22 | 4.22 |
| следующий | 23 | 4.23 |

Не уменьшайте `versionCode`.

# 6. Как собрать подписанный APK

Для публикации нужен **release APK**.

В Android Studio:

```text
Build
→ Generate Signed Bundle / APK
→ APK
→ Next
```

Выберите:

```text
Choose existing...
```

Укажите существующий файл:

```text
fabula-keystore.jks
```

### Важно

Ключ находится **вне проекта** и не должен попадать в GitHub или в ZIP проекта.

Введите:
- пароль хранилища;
- alias: `fabula`;
- пароль ключа, если Android Studio его запросит.

Далее:

```text
release
```

Для старого совместимого способа подписи используйте:

```text
V1 + V2
```

Затем:

```text
Create
```

Обычно готовый файл появляется здесь:

```text
app/build/outputs/apk/release/app-release.apk
```

Если Android Studio показывает другую папку в финальном окне, ориентируйтесь на неё.

# 8. Публикация на GitHub

Репозиторий приложения и репозиторий обновлений выполняют разные задачи.

Для нового APK:

1. Откройте GitHub.
2. Перейдите в репозиторий приложения.
3. Откройте **Releases**.
4. Нажмите **Draft a new release**.
5. Создайте новый тег.

Например:

```text
v4.21
```

Для следующей версии:

```text
v4.22
```

6. Добавьте файл:

```text
app-release.apk
```

7. Добавьте описание изменений.
8. Нажмите **Publish release**.

# 9. КРИТИЧЕСКИ ВАЖНО: version.json

Автообновление Fabula Audio получает информацию из:

```text
https://raw.githubusercontent.com/Fabula-Audio/updates/main/version.json
```

Откройте репозиторий:

```text
Fabula-Audio/updates
```

Найдите:

```text
version.json
```

В нём необходимо обновить:

```json
{
  "latest_version": "4.21",
  "download_url": "ССЫЛКА_НА_НОВЫЙ_APK",
  "changelog": "Описание изменений"
}
```

### Что изменить

**1. latest_version**

Поставьте новую версию:

```json
"latest_version": "4.22"
```

**2. download_url**

Укажите ссылку именно на APK новой версии.

**3. changelog**

Напишите короткое описание изменений.

После этого:

```text
Commit changes
```

### Почему это критично

Если APK уже опубликован, но `version.json` не обновлён, приложение продолжит получать старую информацию о доступной версии.

То есть публикация APK сама по себе **не завершает выпуск обновления**.

Полная последовательность:

```text
Изменить код
      ↓
Увеличить versionCode/versionName
      ↓
Собрать release APK
      ↓
Проверить APK
      ↓
GitHub Release
      ↓
Загрузить app-release.apk
      ↓
Обновить version.json
      ↓
Commit changes
      ↓
Проверить автообновление
```

# 10. Как проверить автообновление

На телефоне должна быть установлена версия ниже новой.

Например:

```text
установлено: 4.21
доступно:    4.22
```

После публикации новой версии:

1. Откройте приложение.
2. Дождитесь проверки обновления.
3. Если появилось предложение обновиться — проверьте номер версии.
4. Начните загрузку.
5. Дождитесь окончания.
6. Запустите установку.
7. После установки проверьте «О приложении».

### Если обновление не приходит

Проверьте по порядку:

- `versionName` в `app/build.gradle`;
- `versionCode`;
- `version.json`;
- `latest_version`;
- `download_url`;
- доступность APK по ссылке;
- что GitHub действительно сохранил изменения;
- что на телефоне установлена более старая версия.

# 11. Резервное копирование

Рекомендуемый минимум:

### Резервная копия проекта

Перед каждой существенной серией изменений:

```text
FabulaAudioAndroid_4.xx_backup
```

Не заменяйте единственную рабочую копию.

### Резервная копия ключа

Файл:

```text
fabula-keystore.jks
```

должен храниться отдельно от проекта.

Сделайте минимум две резервные копии в разных безопасных местах.

### Пароли

Пароли от keystore нельзя хранить внутри проекта, `gradle.properties`, GitHub или в открытом README.

Если пароль потерян, восстановить его обычным способом нельзя.

# 12. Что делать при «keystore password was incorrect»

Проверьте:

1. Выбран именно `fabula-keystore.jks`.
2. Alias указан как:

```text
fabula
```

3. Пароль введён без лишних пробелов.
4. Используется правильная раскладка клавиатуры.
5. Вы не перепутали пароль хранилища и пароль ключа.

Не создавайте новый ключ только из-за одной ошибки ввода.

---

# 13. Ошибка «Unresolved reference: BuildConfig»

В `app/build.gradle` должно присутствовать:

```groovy
buildFeatures {
    buildConfig = true
}
```

После изменения:

```text
Build → Clean Project
Build → Make Project
```

---

# 14. Ошибка «APK not installed»

Если Android сообщает, что APK не устанавливается после уже установленной версии:

- проверьте подпись;
- убедитесь, что новый APK подписан тем же `fabula-keystore.jks`;
- проверьте `versionCode`;
- не устанавливайте поверх старой версии APK, подписанный другим ключом.

Если приложение было собрано другим ключом, Android может потребовать удалить старую установку.

---

# 15. Если приложение предлагает старую версию

Проверяйте именно:

```text
Fabula-Audio/updates/version.json
```

Особенно:

```json
"latest_version"
```

и:

```json
"download_url"
```

Частая ошибка:

```text
APK = новая версия
version.json = старая версия
```

В таком случае система обновлений будет ориентироваться на `version.json`.

# 16. Цветовая система Fabula Audio

Текущая палитра:

| Назначение | Цвет |
|---|---|
| фон | `#C3E8BD` |
| панели / карточки | `#9DDBAD` |
| основные кнопки | `#5B7553` |
| вторичные элементы | `#8EB897` |
| основной текст | `#040403` |

Основная идея:

```text
светлый фон
   ↓
мягкие зелёные панели
   ↓
тёмный приглушённый зелёный для действий
   ↓
чёрный текст
```

Не добавляйте случайные фиолетовые, лавандовые или кричащие цвета.

---

# 17. Как правильно добавлять новый цвет

Сначала добавьте смысловое имя в:

```text
app/src/main/res/values/colors.xml
```

Например:

```xml
<color name="fabula_example">#8EB897</color>
```

Затем используйте:

```kotlin
getColor(R.color.fabula_example)
```

Не вставляйте в Kotlin значения вроде:

```kotlin
Color.parseColor("#123456")
```

если для этого цвета можно использовать ресурс.

Так палитру можно будет изменить централизованно.

# 18. Статус записи фрагмента

В режиме записи статус должен быть:

```text
не записан
идёт запись…
записан
```

После успешной записи статус становится:

```text
записан
```

и отображается зелёным цветом.

При добавлении новой логики записи обязательно проверяйте:

1. запись действительно создала файл;
2. файл имеет размер больше нуля;
3. состояние модели фрагмента обновилось;
4. `renderFragments()` вызван после изменения;
5. цвет статуса соответствует состоянию.

# 19. Добавление функции «Связаться с разработчиком»

Для Android-почты используется:

```kotlin
val uri = Uri.Builder()
    .scheme("mailto")
    .path("fabula.audio@yandex.ru")
    .appendQueryParameter(
        "subject",
        "Fabula Audio — вопрос/предложение"
    )
    .build()

startActivity(Intent(Intent.ACTION_SENDTO, uri))
```

Используйте `ACTION_SENDTO`, а не общий `ACTION_SEND`, чтобы открывался именно почтовый клиент.

Если почтового приложения нет, покажите понятное сообщение пользователю.

# 22. Главное правило для будущих изменений

Если задача касается только интерфейса, не переписывайте аудиодвижок.

Если задача касается записи, не меняйте квантование.

Если задача касается автообновления, не меняйте запись и FFmpeg.

Работайте маленькими изменениями:

```text
одна задача
   ↓
изменение
   ↓
сборка
   ↓
тест
   ↓
резервная копия
   ↓
следующая задача
```

Так проще понять, какая именно правка вызвала проблему.
