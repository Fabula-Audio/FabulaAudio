# FabulaAudio 4.11 fixed21 — changelog

## Главный фикс: единый источник результата

### `app/src/main/java/com/fabula/audio/MainActivity.kt`
- `processedFile` заменён на `currentResultFile: File?`.
- Единственное присваивание результата выполняется в `publishCurrentResult(file)` после успешного построения выбранного этапа.
- `ПРОСЛУШАТЬ РЕЗУЛЬТАТ` использует только `currentResultFile`.
- `СОХРАНИТЬ РЕЗУЛЬТАТ` использует только `currentResultFile` и больше не вызывает `ensureStage(currentStage)`.
- Убрано повторное вычисление результата в обработчике сохранения.
- При изменении настроек подготовки или выборе нового режима старый `currentResultFile` сбрасывается до нового успешного результата.
- Добавлены диагностические логи:
  - `FABULA_PLAY: mode=<режим> src=<файл> dur=<сек>`
  - `FABULA_SAVE: mode=<режим> src=<файл> dur=<сек>`
- Для одного режима `src` в этих двух логах берётся из одной и той же `currentResultFile`.
- Фактическая первопричина в 4.10: `saveResult()` повторно выполнял `ensureStage(currentStage)` и затем присваивал результат переменной сохранения (`MainActivity.kt`, строка 713 в 4.10). Это создавало второй путь выбора исходного файла вместо использования уже опубликованного результата.
- Сохранение использует суффикс фактического режима: `_x6.flac`, `_x144.flac`, `_x432.flac`.
- Временный файл громкости теперь отдельный для режима: `Fabula_result_save_<mode>.flac`.
