# FabulaAudio 4.7 fixed17 — changelog

## Главное исправление: конкатенация выполняется внутри одного FFmpeg-вызова этапа

В 4.6 ускоренный фрагмент и его конкатенация выполнялись отдельными FFmpeg-вызовами. В новой версии каждый этап `×6`, `×144` и `×432` выполняется **одним** вызовом FFmpeg: исходный файл передаётся через несколько `-i`, каждый вход получает свою `atempo`-цепочку, после чего все ускоренные потоки соединяются `filter_complex concat`.

Это исключает ситуацию, когда в реальной цепочке остаётся только ускоренный фрагмент и итог звучит как однократное ускорение в 432 раза.

### Этап ×6

- `atempo=2.0,atempo=2.0,atempo=1.5`
- 6 входов одного исходного файла в одном FFmpeg-вызове.
- 6 ускоренных потоков → `concat=n=6:v=0:a=1`.
- Для входа 112 с ожидается около 18.667 с на каждый ускоренный поток и около 112 с после concat.

### Этап ×144

- `atempo=2.0,atempo=2.0,atempo=2.0,atempo=3.0`
- 24 входа одного файла в одном FFmpeg-вызове.
- 24 ускоренных потока → `concat=n=24:v=0:a=1`.
- Для входа 112 с ожидается около 4.667 с на каждый ускоренный поток и около 112 с после concat.

### Этап ×432

- `atempo=2.0,atempo=1.5`
- 3 входа одного файла в одном FFmpeg-вызове.
- 3 ускоренных потока → `concat=n=3:v=0:a=1`.
- Для входа 112 с ожидается около 37.333 с на каждый ускоренный поток и около 112 с после concat.

## Самопроверка длительности

После каждого этапа concat пишется:

```text
FABULA_DUR: x6: in=... out=...
FABULA_DUR: x144: in=... out=...
FABULA_DUR: x432: in=... out=...
```

При расхождении более 1 секунды дополнительно пишется `FABULA_DUR` с предупреждением `concat сломал длину`, после чего обработка завершается ошибкой этапа.

## Шумоподавление

Добавлены настройки в UI:

- `Шумоподавление` — по умолчанию включено.
- `Уровень подавления, дБ` — 0..24, шаг 1, по умолчанию 12 → `afftdn=nr`.
- `Пол шума, дБ` — −60..−10, шаг 1, по умолчанию −25 → `afftdn=nf`.
- Используется строго `afftdn=nr=<X>:nf=<Y>`, без `tn` и `tr`.
- Этап выполняется после ×144 и перед ×432.
- Для режима ×6 шумоподавление не запускается, потому что результат этого режима заканчивается после ×6.
- Для режима ×144 шумоподавление не запускается, потому что результат этого режима заканчивается после ×144.
- Для ×432 и `Все вместе` этап запускается только при включённом чекбоксе.

Артефакты типа «бульканья» могут уменьшаться при снижении `nr` или при полном отключении чекбокса. Ползунки оставлены как пользовательский инструмент подбора характера шумоподавления.

Значения и состояние сохраняются в `SharedPreferences`.

## Кнопки

Все управляющие кнопки получили ярко-жёлтый фон `#FFD400` и чёрный текст. Выбранный режим дополнительно выделяется `#FFC107` и тёмной обводкой.

## EQ / АЧХ

Сохраняется прежняя политика 4.6: `ENABLE_AUDACITY_EQ = false`.

Причина — две контрольные точки из документации проекта не дают безопасного полного восстановления исходной кривой Audacity. В коде оставлена корректная FFmpeg-форма кривой через `firequalizer` + `cubic_interpolate` и плоские крайние точки, но по умолчанию этот потенциально сильно окрашивающий EQ не включается. Это предотвращает возврат ранее обнаруженного «подводного» тембра.

## Ускорение / тональность

В проекте отсутствуют `asetrate`, `aresample`, `setrate` и `rubberband`. Ускорение выполняется только через `atempo`.

## Логирование FFmpeg

Каждый вызов FFmpeg логируется целиком:

```text
Log.i("FABULA_CMD", "<этап>: <команда целиком>")
```

Искать в Logcat по тегу `FABULA_CMD`.
