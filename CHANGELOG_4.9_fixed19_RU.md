# FabulaAudio 4.9 fixed19 — changelog

## app/src/main/java/com/fabula/audio/MainActivity.kt
- Убран автозапуск аудио после выбора трека и папки. Воспроизведение начинается только кнопкой «ПЛЕЙ».
- Подготовка оригинала теперь использует только ручные `adeclick` и `afftdn` с текущими настройками.
- Полностью удалены FilterCurve/EQ, `firequalizer`, `loudnorm`, `dynaudnorm`, `compand`, `acompressor` и автокоррекция.
- Дефолты шумоподавления изменены на `nr=6`, `nf=-30`.
- Добавлена live-пересборка во время прослушивания: позиция запоминается, окно около текущей позиции пересобирается в фоне, после чего MediaPlayer возобновляет воспроизведение с той же позиции. Дебонс 400 мс; после 3 секунд показывается «Применяю…».
- Для ускоренных этапов live-прослушивание обрабатывает окно уже текущего этапа, а при построении следующего этапа полная цепочка пересобирается из актуальной подготовки. Это не меняет сохранённый этап до явного построения/сохранения.
- Удалена кнопка «Все вместе». Остались ×6, ×144, ×432.
- Этапы стали последовательными: подготовка → ×6 (`atempo=6`, 3 копии) → ×144 (`atempo=4,atempo=6`, 6 копий) → ×432 (`atempo=3`, 3 копии).
- При запросе ×144 автоматически строится отсутствующий ×6; при запросе ×432 автоматически строятся отсутствующие ×6 и ×144.
- Файлы этапов: `cache/fabula_clean.flac`, `cache/fabula_stage6.flac`, `cache/fabula_stage144.flac`, `cache/fabula_stage432.flac`.
- После каждой конкатенации логируется `FABULA_DUR`. Для новой последовательной схемы `in` в строке этапа — ожидаемая длительность после concat, `out` — фактическая; проверяется отклонение не более 1 с.
- Сохранение теперь сохраняет выбранный этап.
- Поле названия сохраняет `setSingleLine(true)`.

## Важное по цепочке длительностей
Новая схема намеренно не возвращает исходную длину на каждом этапе: для исходника 112 с ожидается ×6 ≈ 56 с, ×144 ≈ 14 с, ×432 ≈ 4.67 с. Это следует из заданных макросов: 6× быстрее + 3 копии, затем 24× быстрее + 6 копий, затем 3× быстрее + 3 копии.
