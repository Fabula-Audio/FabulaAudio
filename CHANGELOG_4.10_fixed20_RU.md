# FabulaAudio 4.10 fixed20 — changelog

## Основа
- Изменён существующий проект `FabulaAudio_Android_4.10_fixed20`; приложение не переписано с нуля.
- Package: `com.fabula.audio`.
- Gradle wrapper: 8.7.
- JDK target: 17 в Android-проекте, проект рассчитан на JDK 21.
- `gradle.properties` сохранён с `-Xmx1024m`, `MaxMetaspaceSize=256m`, `parallel=false`, `workers.max=1`, `caching=false`.

## 1. Раскладка управления
Изменён:
- `app/src/main/res/layout/activity_main.xml`

Добавлена сетка 2×2 одинаковых жёлтых кнопок:
- слева сверху — `▶ ПЛЕЙ`;
- справа сверху — `▶ НАЧАТЬ ОБРАБОТКУ`;
- слева снизу — `ПРОСЛУШАТЬ РЕЗУЛЬТАТ`;
- справа снизу — `СТОП`.

Кнопки используют `#FFD400`, чёрный текст. Выбранная скорость использует `#FFC107` и обводку `#8B6914`.

`Плей` запускает прослушивание текущего этапа и допускает живое переприменение подготовки. `Прослушать результат` воспроизводит уже построенный текущий этап без автозапуска при выборе файла/режима.

## 2. Точная семантика ускорения по trace Audacity
Изменён:
- `app/src/main/java/com/fabula/audio/MainActivity.kt`

По `log.txt` сохранена буквальная семантика:
- ×6: `atempo=6`, затем **6** последовательных копий ускоренного фрагмента;
- ×144: от stage6 `atempo=4,atempo=6` (=×24 относительно stage6), затем **24** последовательные копии;
- ×432: от stage144 `atempo=3`, затем **3** последовательные копии.

Каждый этап строится одним FFmpeg-вызовом: несколько `-i` одного файла + `filter_complex` + `concat`.

Для исходника 112 с ожидаются фрагменты:
- ×6: 112 / 6 = 18.667 с;
- ×24: 112 / 24 = 4.667 с;
- ×3: 112 / 3 = 37.333 с.

После конкатенации:
- `stage6` ≈ 112 с;
- `stage144` ≈ 112 с;
- `stage432` ≈ 112 с.

После каждого concat пишется `FABULA_DUR: <этап>: in=<сек> out=<сек>` и проверяется `|out-in| <= 1 с`. При превышении пишется `FABULA_DUR` warning и этап считается ошибочным.

## 3. Сохранение результата через SAF DocumentFile
Изменены:
- `app/src/main/java/com/fabula/audio/MainActivity.kt`
- `app/build.gradle`

Добавлена реальная зависимость Maven Central:
- `androidx.documentfile:documentfile:1.0.1`

Сценарий:
- диалог содержит обязательное однострочное поле `Название трека` (`setSingleLine(true)`) и необязательное `Описание`;
- пустое название не сохраняется и подсвечивается ошибкой;
- выбранный этап подготавливается в фоне;
- громкость сохраняемого файла применяется FFmpeg через `volume=<значение>`;
- файл создаётся в запомненной SAF tree-папке через `DocumentFile`;
- имя: санитизированное название + `.flac`;
- описание: рядом `<санитизированное название>.txt`;
- существующие файлы с тем же именем заменяются;
- закреплённое право записи проверяется через `persistedUriPermissions`;
- при `SecurityException` показывается `Выберите папку сохранения`, после выбора сохранение автоматически повторяется;
- успех: `Сохранено: <имя>` и `Log.i("FABULA_SAVE", "ok: <uri>")`;
- любая прочая ошибка: `Log.e("FABULA_SAVE", ...)` + Toast с причиной.

## 4. Что сохранено из 4.9
- Нет автозапуска после выбора трека или режима.
- Подготовка: `adeclick` и/или `afftdn=nr=<0..24>:nf=<-60..-10>`.
- Дефолты шумоподавления: `nr=6`, `nf=-30`.
- Нет EQ/FilterCurve, loudnorm, dynaudnorm, compand, acompressor, auto correction.
- Живое применение настроек с debounce 400 мс и сохранением позиции.
- Три режима: ×6 / ×144 / ×432; кнопки «Все вместе» нет.
- Запоминаются источник и папка сохранения.
- `smart-exception-java:0.2.1` сохранён.
- FFmpeg запускается в `Thread`; используется `q(...)` и `check(ReturnCode.isSuccess(...))`.

## Проверка
Полный Gradle build в среде подготовки не запускался: среда не имеет доступа к `services.gradle.org`, поэтому отсутствие сетевой ошибки не должно трактоваться как успешный Android build. Выполнены статические проверки XML, `R.id`, `gradlew` и Kotlin-парсинга без Android classpath.
